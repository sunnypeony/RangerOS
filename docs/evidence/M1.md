## 改动摘要

- `drivers/vga.c`：80×25 文本模式，0xB8000，属性 0x07；支持 `\n`、`\r`、`\b`、`\t`、第 80 列自动换行、末行后滚动、硬件光标。
- `lib/format.c`：基于回调的格式化器，支持 `%c %s %d %i %u %x %X %p %%`、宽度（上限 32）、`0` 与 `-` 标志；不支持精度、长度修饰符和浮点。
  `kprintf` 同时输出到串口与 VGA；串口诊断保留。
- `arch/i386/gdt.c`、`gdt_load.asm`：自有 3 项平坦 GDT（0x08 code、0x10 data），`lgdt` 后用 mov 重载数据段，用远跳转重载 CS。
- `arch/i386/isr.asm`、`idt.c`、`trap.c`、`trapframe.h`：256 个中断门存根，统一的 trap frame（偏移由 `_Static_assert` 固定）；
  isr_common 对齐栈后调用 C；诊断包含 vector、名称、error code、EIP、CS、EFLAGS、通用寄存器、段寄存器、frame 地址；
  只有 vector 14 才打印 CR2；之后调用 `panic()` 并停机。
- `kernel/panic.c`：`PANIC <消息>` + `HALT`，然后 `cli; hlt` 循环，带嵌套保护。
- `lib/string.c`：memset/memcpy/memmove（编译器可能自动生成对它们的调用）。
- 测试专用：`tests/kernel/selftest_{ud,gp,vga}.c`，以及用 `-DRANGEROS_SELFTEST` 重编的 kmain；`build/kernel.elf` 中没有 selftest 符号（已用 nm 确认，计数为 0）。
- 工具：run_qemu.py 增加 QEMU monitor 采集（`pmemsave` 文本缓冲区、`screendump` 截图）；新增 check_vga.py、check_exception.py、m1_test.sh、tests/host/test_format.c。
- `make test` = M0 回归 + M1；新增 `make test-m1`、`make host-test`、`make run-vga`。
- 未实现 PIC/PIT/键盘/调度/分页/用户态；全程不执行 `sti`。

## VGA 验收方法（不以串口代替）

QEMU 以 `-display none` 运行（不是 `-nographic`，VGA 设备仍在）。内核到达终态并保持 1 s 后，测试运行器经 QEMU monitor 执行：

- `pmemsave 0xb8000 4000 "<文件>"`：读取 VGA 设备 0xB8000 处的文本缓冲区（80×25×2 字节），由 check_vga.py 解码，逐行比对字符与属性；
- `screendump <文件>.ppm`：QEMU 实际渲染出的 720×400 画面，转成 PNG 作为截图证据（M1-logs/*.png）。

VGA 内容来自显存，不来自串口日志。`vga-scroll` 自检**只写 VGA、不写串口**（串口只输出开始和结束标记），整屏 25 行由 check_vga.py 独立模拟后逐格比较，因此这个用例无法靠串口文本通过。

## 已知限制

- 所有向量都是致命的；没有可恢复的异常处理，返回路径未测试。
- #DF 没有独立 TSS 栈：内核栈溢出会导致 triple fault（测试会判为 EARLY_EXIT，但没有专门用例）。
- 未重映射 PIC；BIOS 默认 IRQ 向量与异常 8–15 重叠，所以 M2 remap 之前绝不能 `sti`。
- NMI（向量 2）按普通异常 panic，没有特殊处理。
- VGA 只用一种颜色；没有光标形状、颜色或宽字符支持。
- 格式化器没有精度、长度修饰符、浮点；宽度上限 32。
- VGA 验证依赖 QEMU 的显存读取和 QEMU 自身的渲染，不代表真实显示器的效果。
- 启动栈没有哨兵（M4a 引入任务栈哨兵）。
- 诊断输出期间串口和 VGA 没有锁（单 CPU、IF=0，当前不需要）。

## 三个学习问题（MILESTONES M1）

1. **GDT 与 IDT 有什么区别？** 提示：GDT 描述的是「段」（基址、界限、权限），由 CS/DS/SS 等选择子引用；IDT 描述的是「向量 → 处理函数入口」，由异常或中断按向量号查找。
   对照 `arch/i386/gdt.c` 与 `idt.c` 中 8 字节描述符的字段，并想一想：为什么 #GP 自检的选择子 0x28 会出错，而 0x10 不会？
2. **谁压入 error code？** 提示：CPU 只为 8、10–14、17、21、29、30 号向量压入 error code，其余向量的 0 是 isr.asm 存根补的。
   比较 `isr_stub_6` 与 `isr_stub_13` 的反汇编（`llvm-objdump -d build/kernel.elf`）；如果存根在 #GP 上也多压一个 0，trap frame 的哪些字段会错位？
3. **iret 与 ret 有什么区别？** 提示：`ret` 只弹出 EIP；`iretd` 弹出 EIP、CS、EFLAGS（跨特权级时还有 ESP、SS），因此会恢复 IF。
   isr_common 的末尾为什么要先 `add esp, 8` 再 `iretd`？如果某个处理函数直接用 `ret` 返回，会发生什么？
