## 改动摘要

- `shell/shell.c`：`help`、`version`、`ticks`、`clear`、`demo`。只在主循环中运行，IRQ1 只负责入队。
- `lib/line_edit.c`：127 字符行加终止符；退格（在行首时不做任何事）；超出部分拒收并计数，超长行整行丢弃，不执行。
- `kernel/wait.c`：`wait_for_input()` 与 `wait_until_tick()`，遵循 `cli; 检查; sti; hlt` 契约，要求进入时 IF=1，否则 panic。
- `keyboard_queued()`；版本号改为 `0.1.0-mvp`。
- 测试：行编辑宿主单测；QEMU PS/2 注入的命令、边界、内核队列满与 2 分钟稳定性用例；VGA 与串口检查。
  run_qemu.py 增加脚本模式（`type`/`key`/`repeat`/`sleep`/`expect`）；新增 check_shell.py；check_vga.py 增加 `--row`；脚本在 tests/m3/。
- **M2 回归用例的调整**：主循环现在把输入交给 shell，所以 VGA 行带有 `> ` 提示符。m2_test.sh 的 kbd-vga 期望由 `^Hi RangerOS 123!$` 改为 `^> Hi RangerOS 123!$`（`ok` 同理）。
  其余 M2 检查（KEY 行重建、KBD 计数、扫描码总数）不变。
- 未实现：调度、分页、用户态、文件系统、串口输入。

### 观察到的事实与原因推断

| 观察（来自日志） | 推断 |
|---|---|
| demo 期间 `queued` 依次为 2、4、6、6、6（m3-cmds.serial.log），demo 结束后紧接着处理了 `ticks` 这一行 | demo 占用主循环时，IRQ1 照常入队；字符留在队列里直到主循环恢复。之所以停在 6，推断是 `ticks` 加 Enter 共 6 个字节在第 3 步之前已全部到达 |
| soak 的 TICKS 序列为 …2000、2100、**2298**、2300…（缺少名义上的 2200）；同一时段日志中有 `demo step 1/5 tick=2218` | 那时主循环正在执行 demo（约 100 tick），到期的报告在 demo 结束后才输出。报告只是推迟，并没有丢失 tick：irq0 计数连续，序列仍然严格递增。首次开发运行中同样的位置是 2292，差异来自时序 |
| queue-full：`chars=128 dropped=12 scancodes=280`，第一行的内容是前 128 个数字 | 140 个键共 280 个扫描码全部经 IRQ1 到达，队列满后丢弃的是新字节。旧内容没有被覆盖，与宿主单测的结论一致 |
| 每次启动 `kbd_empty=1`（与 M2 相同） | i8042 初始化清空缓冲区时，PIC 锁存了一次 IRQ1 边沿（M2 的推断，未进一步验证） |
| soak 墙钟 122.5 s，最后 `ticks=12036` | QEMU TCG 的 PIT 跟随宿主时钟，所以 tick 与墙钟大致一致。这只是观察，不作为频率合格的依据（SPEC D04） |

## 已知限制

- shell 是单线程主循环：命令执行期间（例如 demo）不处理新输入，但输入会排队（最多 128 字节）。
- 超长行整行丢弃，不截断执行；没有命令历史、光标移动、Tab 补全和参数。
- 交互输入只来自 PS/2；`make run` 的串口终端不能输入命令，请用 `make run-vga`。
- 串口诊断日志（KEY/SHELL/KBD/TICKS）对每个字节都输出一行，很啰嗦；这是为了测试与审查有意保留的。
- 键盘布局、扫描码集合与 M2 相同（美式 set 1，键位有限）。
- 栈仍然没有哨兵。

## 三个学习问题（M3）

1. **为什么命令解析放在主循环而不是 IRQ1 里？** 提示：对照 interrupts.md §2。如果在 IRQ1 中执行 `demo`（它要等 100 tick），IF=0 期间 IRQ0 能否到达？`wait_until_tick` 的 panic 检查会发生什么？
2. **`cli; 检查; sti; hlt` 为什么不会丢失唤醒，而 `检查; hlt` 会？** 提示：设想 IRQ1 恰好在检查队列为空之后、`hlt` 之前到达。为什么 `sti` 的「延迟一条指令」很关键？如果 PIT 被屏蔽，第二种写法最坏会怎样？
3. **超长行为什么选择丢弃而不是截断执行？** 提示：输入 `ticks` 再加 123 个空格，截断之后它仍然是一条合法的 `ticks`；如果是 `clear` 加上一个超长参数呢？对照 line_edit.h 中 `rejected` 的语义，以及 #6 中 127 字符与 128 字符两种情况的不同结果。
