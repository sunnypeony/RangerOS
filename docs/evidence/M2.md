## 改动摘要

- **IRQ 分发**（arch/i386/trap.c、kernel/irq.c）：`isr_dispatch` 把 0x20–0x2F 交给 `irq_dispatch` 并**返回**；CPU 异常仍走原来的致命诊断路径 `fatal_trap()`。
  每个 IRQ 依次执行：计数 → 设备处理函数 → EOI → 返回 → `iretd`。另外记录 EOI 次数、spurious、unexpected、最大嵌套深度，以及处理函数中出现 IF=1 的次数。
- **PIC**（drivers/pic.c）：初始化前后都屏蔽全部线路，remap 到 0x20/0x28，只解除 IRQ0 和 IRQ1 的屏蔽，读回 IMR：0xfc/0xff。IRQ7/15 检查是否为 spurious。
- **PIT**（drivers/pit.c）：通道 0，模式 2，除数 11932（目标 100 Hz）。IRQ0 只做 `pit_ticks++`。tick 是 32 位，比较使用跨回绕安全的 `tick_reached()`。
- **键盘**（drivers/keyboard.c、lib/kbd_decode.c）：i8042 开启 translation，所以 CPU 收到 set 1 扫描码。支持字母、数字、空格、Enter、Backspace 和左右 Shift。
  break 码、E0 扩展序列、E1（Pause）序列和控制器应答都安全忽略。IRQ1 只读取、解码、入队和计数。
- **输入队列**（lib/input_queue.c）：固定 128 字节；满时丢弃新输入、`dropped++`，旧内容不被覆盖。
- **同步**（arch/i386/irqflags.h）：`irq_save()`/`irq_restore()` 保存并恢复原 IF，带编译器屏障；处理函数中不执行 `sti`；`sti` 只在初始化完成后执行一次。
- **主循环**（kernel/kmain.c）：消费队列，在 VGA 上回显，串口每个字节输出一行 `KEY`；每 100 tick 在串口输出一行 `TICKS` 状态；用 `cli; 检查; sti; hlt` 进入 idle。不解析命令，没有 shell。
- **测试**：宿主单测（队列、解码器）；QEMU 中的 TICKS/EOI 检查；IRQ 返回自检及其破坏版负向用例；经 QEMU monitor `sendkey` 的 PS/2 注入；VGA 采集；新增 check_irq.py、check_kbd.py、m2_test.sh。
  run_qemu.py 增加 `--sendkey`/`--expect-after`，并且 monitor 命令返回错误时报 ERROR（以前会静默忽略）。
- M1 的 selftest 接口改为 `selftest_run(stage)`（EARLY / IRQ_ON），行为不变。
- 未实现：调度、shell、分页、动态分配、从片 IRQ、键盘 LED/typematic。

#### 扫描码计数

`sendkey` 经 QEMU 的 PS/2 键盘模型发送 set 1 字节：带 Shift 的键 4 个字节（Shift make、键 make、键 break、Shift break），其余 2 个字节。
22 个键中有 5 个带 Shift，所以总数为 5×4 + 17×2 = **54**，其中 22 个产生字符，32 个被忽略。
KBD 行在最后一个 Enter 还处于按下状态时打印（sendkey 约 100 ms 后释放），所以 KBD 行显示 53（第一行同理显示 47 = 48 − 1）。
完整的 54 出现在之后的 TICKS 行里。每次启动都有一次没有数据的 IRQ1（`kbd_empty=1`），见 interrupts.md §4.1。

## 已知限制

- 单线程主循环，尚无任务调度：IRQ 只记录事件，所有处理和打印都在主循环中完成。
- TICKS 行每秒一次，只输出到串口；VGA 只显示回显内容。
- 键盘：不支持 Caps Lock、Ctrl/Alt、方向键、符号键、小键盘、LED、typematic；没有键盘 reset 或自检命令，依赖 BIOS/GRUB 已初始化的设备。
- 输入只有最近一次 Enter 前后的回显，没有行编辑（M3 shell 负责）。
- 启动时总有一次没有数据的 IRQ1（被锁存的边沿），处理为 `empty`。
- PIT 频率是名义值（约 99.998 Hz），不宣称墙钟精度。
- IRQ 返回自检的探针直接读取 `pit_ticks`（对齐的 32 位读取），这是测试代码中唯一不经过临界区的共享变量访问。
- 栈仍然没有哨兵；IRQ 现场需要被打断代码栈顶以下约 68 字节加上处理函数的调用链。

## 三个学习问题（MILESTONES M2）

1. **为什么要 remap？** 提示：BIOS 默认把主 PIC 的 IRQ0–7 映射到向量 0x08–0x0F。对照 trap.c 中的 `exception_names` 表：
   如果不 remap，IRQ0（定时器）和哪个 CPU 异常共用同一个向量？仅凭 trap frame 能否区分两者（考虑 error code 的有无）？
2. **EOI 做什么？** 提示：试着在 `irq_dispatch` 里注释掉 `pic_send_eoi(irq)` 再运行 irq-ticks 测试，tick 会停在多少？
   为什么在 IF=0 时发 EOI 不会造成嵌套？对照 interrupts.md §2 的流程图。
3. **为什么 volatile 不够？** 提示：看 `input_queue_pop` 对 `head`、`count`、`buf[]` 的读-改-写。如果主循环执行到一半时 IRQ1 调用了 `input_queue_push`，会发生什么？
   `irq_save()` 的 `"memory"` clobber 解决的是哪一半问题，`cli` 解决的又是哪一半？
